# CuteCut Pro - Current Engine Execution Path & Forensic Audit

This document traces the exact path of the current client-side alignment engine in `src/utils/quranAlignmentEngine.ts` and examines whether true CTC speech recognition is running.

---

## 1. Trace of the Current Engine Pipeline

The client-side engine aligns Quranic text to audio using the following sequence of operations:

1. **Audio Input**: Receives an audio stream or pre-extracted silent segment intervals (`options.pcmData`, `options.sampleRate`, `options.acousticSegments`).
2. **Acoustic Observation Layer**:
   - If raw PCM data is provided, it extracts Voice Activity Detection (VAD) observations using simple signal characteristics (RMS, Spectral Flux, Zero Crossing Rate).
   - It identifies speech onsets and offsets as candidate boundaries.
3. **Phonetic Normalization**:
   - `normalizeQuranicPhonetics` strips vocalic diacritics (harakat), simplifies letters (e.g., collapses Ta Marbouta to Ha), and cleans Uthmani text.
   - It calculates a **nominal duration** for each verse based on its normalized syllable count.
4. **Fallback Candidate Generation**:
   - If no raw audio or VAD observations are present, the engine automatically creates artificial candidates by **dividing the total audio duration proportionally** among all verses based on their nominal syllable count.
5. **Viterbi Dynamic Programming Alignment**:
   - `runViterbiSequenceAlignment` constructs a dynamic programming trellis to match the phonetic models of the verses with the acoustic boundary candidates.
6. **Local Boundary Refinement**:
   - `refineBoundaryLocally` shifts boundaries slightly to the closest high-sharpness acoustic candidate within a window of ±1500 ms.
7. **Word-Level Proportioning**:
   - `alignWordsToAcousticSpan` distributes word boundaries proportionally within each verse's aligned boundary.
8. **Arabic/Translation Display**:
   - Subtitles are generated and placed on the timeline, matching the final segments.

## 2. Forensic Search for True Speech Recognition (CTC/ASR)

A deep audit of the codebase was conducted to find markers of actual neural speech recognition:

* **CTC Model Loading**: None. No PyTorch, TensorFlow, ONNX, or WebAssembly neural model files are loaded.
* **CTC Logits / Tokenizer / Acoustic Model Inference**: Absent. No acoustic frame emission calculations or neural tokenizers exist in the client codebase.
* **recognizedWords / word timestamps / phoneme timestamps**: These are accepted as optional parameters (`options.recognizedWords`), but are empty and never generated by the client code itself.

### Concluding Statement:
> **"Current engine is not performing true CTC forced alignment."**

There is no actual Speech-to-Text, Whisper, or Wav2Vec2 running on the client side. The engine is a client-side heuristic/acoustic onset-offset sequence-fitting algorithm that simulates alignment. Heuristic duration matching and syllable ratio curves must not be described as genuine speech recognition.
